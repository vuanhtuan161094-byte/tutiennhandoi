## Concrete implemented candidate

The new **Ngự Khí Cast visual layer** is a presentation-only Godot 4.7.2 Node2D script, with an isolated 390×844 showroom scene loading the real existing Tử Mị cast rig:

- [`ngukhi_cast_vfx.gd`](ngukhi_cast_vfx.gd): deterministic 1.5-second cycle with 3 overlapping/split flying-sword trajectories, arc trails, a jade–violet–gold command sigil, anticipation and impact burst.
- [`ngukhi_cast_stage.gd`](ngukhi_cast_stage.gd): stand-alone scene driver using the existing `ngukhi_tumi_animation_pilot/rig/tu_mi_cast_rig.tscn`, never creating a fake replacement portrait. The prior small ring/treasure visuals are hidden *only inside this preview instance* to avoid double painting.
- [`ngukhi_cast_stage.tscn`](ngukhi_cast_stage.tscn): preview scene; desktop click/tap restarts cast. The floating circle on the right is a **non-gameplay dummy**, not a Monster/Boss asset.

This first implementation is a separate **visual cue prototype**. It has **not** replaced CombatScreen, canonical skill routing, damage, targeting, SaveService, or any `art/approved` asset.

## Distinctive phases

| Normalized phase | Cue |
| --- | --- |
| 0.00–0.30 | Tụ khí: sigil builds and three command cores orbit hand |
| 0.34–0.49 stagger starts | Pháp bảo: staggered swords launch on quadratic arcs, jade core + violet trail |
| 0.68–0.92 | Contact impact: expanding ring, radial shards, white–jade flash |
| 0.92–1.00 | Recovery and fade; preview loop resets |

The 1.5-second candidate cycle is **not** skill gameplay timing. It must be re-timed from authoritative cast/start/hit events before production integration; do not use it to infer cooldown or actual hit time.
