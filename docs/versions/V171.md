# V171 — Endgame / Immortal / Dao Suy Runtime Authority Consolidation

Status: CLOSED / LOCKED.

## Objective

Close proven restore-time authority leaks in the endgame path without changing authored balance. Scope is limited to Immortal/Dao Suy/Manifestation canonicalization after restore. New-life carry-over was audited in the same pass and did not require a patch.

## Proven findings fixed

1. Restore trusted authored Immortal progression axes directly from save. Values that live mutation caps at `0..100` could therefore be restored above canonical bounds and feed combat scaling.
2. `manifestationCapacity` could preserve a forged high saved value because realm synchronization only raised capacity with `Math.max(...)`.
3. Restored `activeManifestationIds` could retain duplicate, over-capacity or no-longer-owned manifestations before runtime resumed.
4. `daoSuyTribulationsPassed` could be lower than the successes recorded in `daoSuyTribulationsPassedByMajor`, even though live success increments both. That inconsistent global count is consumed by Dao Suy relief logic.

## B1 — Immortal restore authority — PASS

- Authored Immortal axes that are live-bounded to `0..100` are clamped to the same canonical range on restore.
- Unbounded counters/authorities remain unbounded but are normalized to finite non-negative values.
- Valid saves retain their authored values exactly.
- `awakened` is derived from canonical realm order instead of trusting a forged save flag.

## B2 — Manifestation authority — PASS

- Manifestation capacity is derived from realm order only: below Huyền Tiên it is `0`; authored realm milestones restore the canonical slot count.
- Active manifestation IDs are deduplicated.
- IDs without current ownership/runtime eligibility are removed.
- Active manifestations are truncated to canonical capacity.
- Existing valid manifestations remain unchanged.

## B3 — Dao Suy consistency — PASS

- Per-major passed counts are normalized to authored `0..5` bounds.
- Global `daoSuyTribulationsPassed` can never restore below the total accounted successful tribulations in the per-major history.
- No Dao Suy probability, relief amount, pill value or progression rate was changed.

## B4 — New-life carry-over audit — PASS / no patch

`buildReincarnatedState()` already creates fresh Soul, Dao, Tribulation and Immortal state for the new life. Immortal/endgame progression is therefore not leaking across Luân Hồi. V170 meta progression remains untouched.

## B5 — Performance preservation — PASS

The first V171 candidate added one eager restore helper module and tripped the locked frontend graph budget (`194 > 193` modules). The helper was then inlined into the already-eager `session-restore.js`; the separate module was removed. No performance threshold was raised.

## Targeted proof

`qa/tests/v171-endgame-runtime-authority-test.js` proves 6 cases:

1. forged/negative Immortal bounded axes are repaired;
2. Manifestation capacity is realm-derived and unowned active systems are removed;
3. Dao Suy total-pass authority reconciles with per-major success history;
4. full `SimulationSession.restore()` applies V171 canonicalization before runtime resumes;
5. valid endgame save values remain unchanged;
6. mortal saves cannot retain Immortal awakening or active manifestations.

The gate is wired into Backend Fast QA.

## Non-goals preserved

No rebalance. V171 does not change:

- realm progression requirements;
- Immortal refinement gains/costs;
- Dao Suy chance/relief/reward formulas;
- Manifestation authored slot milestones;
- combat coefficients;
- Luân Hồi RP/Potential/Fate/Tree authority locked in V170;
- Genesis/world rewards or economy rates.
