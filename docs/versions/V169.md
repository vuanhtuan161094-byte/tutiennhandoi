# V169 — Động Phủ / Phân Thân / Offline Runtime Authority Consolidation

Status: OPEN — next implementation scope.

## Objective

Consolidate the idle/offline authority path without rebalancing authored values. V169 must prove that Động Phủ facilities, six Lục Đạo Phân Thân, dungeon workers/assignments, offline elapsed time/caps and Reincarnation automation modifiers each have one state authority and one settlement path.

## Source seams to audit first

- `dist/core/dongfu-v99.js`
- `dist/core/soul.js`
- `dist/core/offline.js`
- dungeon/session worker and assignment paths
- standalone/session offline restore/settlement paths
- Reincarnation talents affecting `automation.cycle`, `dungeon.expedition`, `clone.parallel`
- save/restore repair and public API/snapshot surfaces

## B1 — State Authority

Define `source → state authority → modifier → consumer → settlement position` for:

- Động Phủ facilities and production modifiers
- six Lục Đạo Phân Thân and realm-gated clone capacity
- Soul pressure / clone specialty efficiency
- dungeon workers and assignments
- offline timestamp, elapsed time and cap
- Reincarnation automation / dungeon / clone talents

`dongfu-v99.js` is treated as a read/composition surface unless source proves it owns mutation. Legacy parallel-worker capacity must not become a second Phân Thân authority.

## B2 — Offline Aggregation

Prove every idle/offline source settles once. Detect and remove only proven duplication/leakage, including:

- login + offline resolver granting the same elapsed period twice
- Hunt offline rewards settling through more than one path
- Soul clone efficiency being applied again by Dungeon/offline code
- Động Phủ facility modifiers being applied at both producer and reward settlement
- stale worker assignment re-adding a retired clone/job

## B3 — Time / Cap Authority

Lock the runtime order:

`real elapsed → canonical cap → world/game time conversion → jobs/actions → rewards/state mutation`

Verify the authored 24h base offline cap and Reincarnation extensions compose once. Guard negative elapsed time, future timestamps and backdated/tampered saves. Do not change the authored clock, caps or production rates.

## B4 — Save / Restore

Adversarial restore must not revive duplicate or retired authority. Cover at minimum:

- duplicate clone IDs or duplicate Lục Đạo slots
- clones beyond realm-authorized capacity
- stale/dangling dungeon worker assignments
- completed jobs restored and settled again
- future/invalid offline timestamps
- retired facility/parallel-worker payloads becoming live modifiers

## B5 — Full Idle Parity

Build one state using Động Phủ + six-clone progression + worker assignment + Reincarnation modifiers and compare:

- source/authority breakdown
- online progression for an authored interval where online/offline semantics are intended to match
- offline settlement for the same interval
- runtime state
- API/UI snapshot

No duplicate rewards, no duplicate efficiency, and no stale save authority may survive.

## Non-goals

- No rebalance.
- Do not change offline caps, Phân Thân strength, Động Phủ discounts, Hunt rewards, production times or authored rates.
- No large refactor/new runtime module when existing authority seams can be extended.
- Do not reopen V162–V168 unless a regression proves it necessary.

## Closure gate

`search → narrow source → audit → minimal patch → V169 targeted proof → Backend Fast → Frontend Fast → Canonical V140→V169`

V169 becomes CLOSED / LOCKED only when every gate is green.
