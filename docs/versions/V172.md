# V172 — Faction Membership Runtime Authority Consolidation

Status: CLOSED / LOCKED.

## Objective

Close a proven restore-time authority leak in faction membership without changing faction progression, economy, cultivation bonuses, facility costs or orthodoxy balance.

## Proven finding fixed

Live faction progression does not allow an ordinary joined faction membership to promote into `leader`; `promoteFactionMembership()` stops before leader. `leader` is created by the player-founded sect path. Restore previously cloned `playerMemberships` unchanged, so a forged save could restore an ordinary joined membership as `leader` or another rank above its earned contribution/realm authority.

That rank is consumed directly by runtime systems for cultivation multiplier, archive access, facility mutation and Elder/Leader-gated orthodoxy actions.

## B1 — Earned rank authority — PASS

- Active joined-faction rank is bounded by the same authored `factionPromotionRequirements` used by live progression.
- Restore uses `lifetimeContribution` plus current max realm order to determine the highest rank that could have been earned.
- Restore only downgrades impossible authority; it never auto-promotes a valid underpromoted save.
- Ordinary joined memberships cannot restore as `leader`.

## B2 — Founder authority — PASS

- Legitimate player-founded faction leaders remain valid.
- Founder eligibility requires the canonical player-created faction identity plus matching `founderLifeId`.
- No new faction, rank, treasury or reward is invented during repair.

## B3 — Membership/member parity — PASS

An active player membership is only retained when its live mirror exists and agrees on the canonical identity:

- membership key / `lifeId`
- target faction existence
- `player:<lifeId>` member row
- player member type
- matching member/source life IDs
- active member state

Dangling or identity-mismatched active membership loses runtime authority instead of receiving invented replacement state. The surviving member rank is synchronized to the repaired membership rank.

## B4 — Numeric repair — PASS

- Invalid/negative `merit` repairs to a finite non-negative value.
- Invalid/negative `lifetimeContribution` repairs to a finite non-negative value.
- Invalid contribution cannot be used to legitimize a restored promotion.

## B5 — Runtime restore parity — PASS

`repairAdventureStateReferences()` now applies faction authority canonicalization before `SimulationSession.restore()` resumes runtime consumers.

The full restore proof verifies that a forged joined-faction leader restores as the earned rank and no longer passes leader/elder facility authority.

## Targeted proof

`qa/tests/v172-faction-membership-runtime-authority-test.js` proves 6 cases:

1. joined faction cannot restore forged leader;
2. repair never auto-promotes an underpromoted valid save;
3. legitimate player-founded leader is preserved;
4. dangling/mismatched active membership loses authority;
5. full `SimulationSession.restore()` repairs rank before runtime consumers;
6. malformed numeric contribution/merit cannot create promotion authority.

The test is wired into Backend Fast QA.

## Performance

No new eager runtime module was added. V172 extends the already-loaded save-stability path and keeps the existing frontend performance gates unchanged.

## Non-goals preserved

No rebalance. V172 does not change:

- faction promotion thresholds;
- faction cultivation bonus values;
- contribution merit values;
- treasury income/costs;
- facility upgrade costs/effects;
- faction service costs;
- orthodoxy costs/rewards/diplomacy formulas;
- inventory rewards or economy rates.
