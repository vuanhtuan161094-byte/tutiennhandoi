# V170 — Luân Hồi / Life Settlement / Meta Progress Runtime Authority Consolidation

Status: CLOSED / LOCKED.

## Objective

Lock one authoritative path from end-of-life settlement into Luân Hồi meta progression and the next life. V170 fixes restore-time authority leaks without changing any authored balance values.

## Proven findings fixed

1. Permanent Potential restore previously derived `lifetimeEarned` with `max(spent allocations, saved earned)`, so a tampered allocation could legitimize unearned permanent stats.
2. Reincarnation Tree ranks were clamped by node rank caps but were not constrained by `tree.lifetimePointsEarned`.
3. Fate unlock IDs could be restored without proving the corresponding `sharedSpentPoints` RP spend.
4. Duplicate `rewardHistory` or archive rows for the same `lifeId` could preserve more than one meta record even though live finalization is intended to be idempotent.

## B1 — Meta budget authority — PASS

- `tree.lifetimePointsEarned` is the sole RP budget authority.
- Tree rank spend + shared/Fate spend cannot exceed earned RP after restore.
- Overspent Tree ranks are deterministically reduced to the paid budget.
- Permanent Potential allocations cannot increase `lifetimeEarned`.
- `allocations + unspent` reconciles exactly to saved earned Permanent Potential.
- Valid saves remain unchanged.

## B2 — Settlement idempotence — PASS

- One life produces at most one finalized progression reward.
- One life produces at most one archive settlement.
- Repeated `finalizeReincarnationRewards()` for the same life returns the existing reward and does not mint RP/Potential again.
- Restore collapses duplicate reward/archive rows by `lifeId`.

## B3 — Fate authority — PASS

- Mortal Fate starters remain free/authored.
- Paid Fate nodes require their authored prerequisite chain and paid shared RP budget.
- Active Fate must be an unlocked valid Fate; invalid/unpaid active Fate falls back to the canonical starter.
- Restore cannot create a free paid Fate node.

## B4 — Save / restore repair — PASS

Restore now repairs invalid/tampered payloads for:

- overspent Tree ranks
- inflated Permanent Potential allocations/unspent values
- unpaid Fate unlocks
- duplicate life reward rows
- duplicate life archive rows

## B5 — Runtime parity — PASS

`qa/tests/v170-reincarnation-meta-runtime-authority-test.js` proves:

`earned meta currency → allocation/unlock → restore → runtime authority → settlement/finalize`

Valid-state behavior remains unchanged; only impossible/overspent/tampered restore states are reduced to their earned budget.

## Non-goals preserved

No rebalance. V170 does not change:

- RP reward formula
- tree node costs or effects
- Fate unlock costs/effects
- Permanent Potential conversion rate
- reincarnation energy cost/recharge
- birth odds/origin rewards
- settlement scoring
