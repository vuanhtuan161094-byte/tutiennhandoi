# V174 — Action Settlement & One-shot Reward Runtime Authority Consolidation

Status: **CLOSED / LOCKED**

## Objective

Close provable one-shot settlement replay authority splits in Content Event and Dungeon first-clear restore paths without changing authored rewards, rates, pacing or progression rules.

## Findings closed

1. **Content Event completion split authority**
   - Successful one-shot Content Event resolution records both `flow.contentEvents.completedEventIds` and `choicesByEventId[eventId]`.
   - Availability blocks replay through `completedEventIds`, while restore previously cloned the two mirrors independently.
   - A save retaining a valid resolved choice but missing the completion-list entry could therefore make an already-settled event available again and reapply its effects/rewards.
   - Restore now validates current-world event/choice pairs, reconstructs completion from the valid union of existing completion IDs and resolved-choice evidence, deduplicates completion IDs and removes dangling/invalid choice mirrors.

2. **Dungeon first-clear split authority**
   - Dungeon guardian settlement determines `firstClear` from `dungeons.highestClearedFloor`.
   - Every live Dungeon first clear also records durable V89 progression evidence as `first-clear.<dungeonId>.<floor>` before the weekly Bound Jade cap is evaluated.
   - Restore previously trusted the Dungeon progress mirror and V89 first-clear ledger independently.
   - A save retaining the V89 settlement ledger but losing/lowering `highestClearedFloor` could replay guardian/resource-PvE first-clear rewards even though the first clear had already been accounted.
   - Restore now raises missing Dungeon clear progress only when a current-world authored floor has matching V89 first-clear evidence. It never lowers legitimate progress, ignores Hunt keys and ignores non-authored floors.

## Audit result outside the patch

- Generic Activity daily/weekly counters were audited for the same replay class.
- No independent period-specific authority was found that can safely reconstruct those counters without potentially blocking legitimate rewards in a later day/week.
- V174 therefore does **not** canonicalize generic Activity counters merely because they are saved fields.

## Implementation

- Runtime repair is kept inside already-eager `dist/core/session-restore.js` as `normalizeCanonicalOneShotSettlementAfterRestore(state, world)`.
- It runs after normal reference repair and before restored runtime consumers resume.
- No standalone eager runtime module was added.
- The locked frontend performance thresholds were not raised.

## Targeted proof

`qa/tests/v174-one-shot-settlement-runtime-authority-test.js` proves 6 cases:

1. A valid Content Event choice mirror reconstructs missing one-shot completion authority.
2. Invalid/dangling Content Event mirrors cannot forge completion authority.
3. A valid Dungeon V89 first-clear ledger reconstructs a missing highest-clear mirror.
4. Hunt keys and invalid/non-authored Dungeon floor keys cannot create Dungeon clear authority.
5. Reconciliation never lowers legitimate Dungeon progress.
6. Full `SimulationSession.restore()` repairs both authority splits before Content Event/Dungeon consumers resume.

## Non-goals

V174 does **not** change:

- Content Event effects, conditions, priorities or rewards;
- Dungeon guardian loot, Resource-PvE rewards, first-clear values or difficulty;
- V89 Bound Jade values, daily/weekly caps or period logic;
- generic Activity reward/cooldown/pacing formulas;
- any V160–V173 locked authority.
