# V163 — Pháp Bảo / Chí Bảo Runtime Authority

Status: ACTIVE
Baseline: V162 CLOSED / LOCKED
Canonical implementation: `main`

## Objective

Consolidate Pháp Bảo / Chí Bảo runtime ownership without changing locked gameplay balance.

The current player-facing system is Collection-based (`artifact` / `relic` inside `collectionV12316`) with V12326 as the public Collection progression authority. A separate legacy `state.artifacts` structure still exists for compatibility/history and has real downstream consumers, so it must not be deleted blindly.

## Initial authority findings

- `app.js` renders Pháp Bảo and Chí Bảo from `model.collectionEconomy` categories `artifact` and `relic`.
- Collection equip/unequip/strengthen/advance actions route through the Collection authority established in V162.
- `dist/core/artifact-v88.js` is the live Pháp Bảo/Chí Bảo combat adapter; it layers current V150/V151 behavior over `artifact-v149-base.js`.
- `dist/core/gameplay.js` explicitly exposes Collection-backed Pháp Bảo as the player-facing artifact view.
- Legacy `state.artifacts` is not the player-facing combat loadout authority, but it is still consumed by late-game integration/history/reincarnation code. Therefore it is compatibility-state with live consumers, not proven dead code.
- The old top-level documentation reference to `game-artifact.js` was stale; that file does not exist on current main.

## Non-negotiable rules

- No balance changes in V163 unless a regression repair requires one and the impact is documented.
- No rename-only migration for version aesthetics.
- No blind deletion of `state.artifacts` or old artifact modules.
- Player-facing Pháp Bảo and Chí Bảo must have one effective combat/read authority.
- Chí Bảo remains a separate one-slot build-law system; it does not consume a Pháp Bảo slot.
