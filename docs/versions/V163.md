## Objective

Consolidate Pháp Bảo / Chí Bảo runtime ownership without changing locked gameplay balance.

V163 established a single player-facing Collection-backed authority while preserving legacy `state.artifacts` only where it still has distinct compatibility/history semantics.

## Final authority map

- Player-facing Pháp Bảo ownership/progression: `state.collectionV12316.items`.
- Equipped Pháp Bảo authority: `state.collectionV12316.activeArtifactIds`.
- Public progression authority: V12326 Collection methods.
- V12325/V12316 public progression names: compatibility aliases only.
- Active Chí Bảo authority: `state.collectionV12316.economyV12325.activeRelicId`.
- Chí Bảo remains a separate one-slot combat-law system and does not consume a Pháp Bảo slot.
- Live Pháp Bảo/Chí Bảo combat adapter: `dist/core/artifact-v88.js` over the locked V149/V150/V151 behavior stack.
- Collection composition boundary: `applyCollectionEconomyToEntityV12325()` -> `applyCollectionToEntityV12316()` once.
- Production combat does not apply legacy `state.artifacts` as a second direct Pháp Bảo gear layer.
- Canonical player-facing read models are `GameplayFacade.overview()` and `GameplayFacade.artifacts()` in the current facade override.

## Retained legacy semantics

`dist/core/artifact.js` / `state.artifacts` was not deleted. V163 proved it still has distinct responsibilities that are not equivalent to Collection Pháp Bảo progression:

- nourishment and Khí Linh awakening;
- ownership-year and battle-history recording;
- saved-loadout legacy compatibility via `legacyArtifactIds`;
- late-game Integration artifact score;
- lost/recovered artifact history;
- world-relic / Luân Hồi archive and recovery flow;
- legacy artifact loot/history naming in combat review.

Save/restore keeps legacy Artifact state, Collection state and meta world-relic state as independent cloned channels.
