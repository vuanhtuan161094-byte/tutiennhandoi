## Scope and actual output

ART-01A V2 is a source-image-based cutout rig, **not AI-generated separate full-body frames**. It uses an arm-free edited Ngự Khí heroine master, normalized source art for both upper arms, forearms and independently controlled hands/wrists, and two discrete hand-seal assemblies. It also retains three separable Ngự Khí treasures as source art without combat-event wiring in this slice.

The user-supplied original character-design image was used for facial identity: a localized face-pixel patch (eyes/nose/lips/skin) is composited using +20/-19 pixel alignment and 4.5px feather. **This does not prove full pixel identity**; user visual approval remains required. Edited master preserves long dark hair, ornate purple/gold costume, gold heels, removes dangling sleeve drapes, and adds black fishnet stockings.

The standalone Godot candidate consists of a Node2D Shoulder → Elbow → Wrist hierarchy per arm, Sprite2D part assets, and an `AnimationPlayer` with one-shot (non-looping) tracks. Playback uses the same deterministic JSON joint data as the Python-rendered QA GIFs. Cast phases: **prepare → raise → seal → command → recover**.

## 2026-11-11 visual re-audit — REJECT FOR ANIMATION / NO PROMOTION

A manual visual review of the **actual delivered** `ART01A_V2_RIG_DARK_390x844.gif` and `ART01A_V2_RIG_LIGHT_390x844.gif` at 54 GIF frames (390x844, total encoded duration measured 2810ms) revealed significant defects **missed by the prior numerical QA**. These are user-visible failures, not merely deferred polish:

1. The shoulder becomes an obvious circular cutout/socket and forearm segments look mechanically inserted rather than anatomically continuous.
2. During raise/transition (~frames 17–20) moving arms overlap or visibly cross torso/chest, breaking anatomy and z-order.
3. The hand-seal crossfades and arm transitions generate duplicated/ghosted hands (notably frames 20 and 35) and detached-looking wrists.
4. The hand-seal images are not consistently connected to the moving forearm/hand joints.
5. The body, hair and dress are essentially static, resulting in mannequin-like motion. Identity does not yet meet the user's strict original-face lock.

The upper-bone-length residual of 0 measured in source coordinates **does not mean visual motion passes**, and a source-rendered GIF is not evidence of Godot runtime. Earlier language suggesting the rig was ready for V3 polish or Godot acceptance was overoptimistic.

**Decision:** V2 is **VISUALLY REJECTED** for production, remain a reference/debug candidate only. Do not integrate it or use it as a basis for scaling 8 Dao. The status in asset registry remains candidate (no user approval); no assets are promoted to approved/locked.

**Required reset:** first achieve a correct seamless shoulder-to-elbow-to-wrist rest pose, mask and heal hidden body pixels, enforce arm z-depth, define wrist-aligned independent hand seals with no opacity double-image, compare a single unchanged identity against the source master, then test only a small 3–5 keypose motion in the same complete full-body framing. Build final Cast and VFX **only after** this passes visual review. A Godot 4.7.2 import/runtime capture is still pending.
